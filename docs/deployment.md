# Deployment Guide — Supabase + Render

This guide takes the project from your laptop to a public HTTPS URL that anyone can open from any device.

```
 GitHub repo ──(auto-deploy on push)──▶ Render web service (Flask + frontend)
                                              │  DATABASE_URL (env var, TLS)
                                              ▼
                                    Supabase PostgreSQL (cloud DB)
```

Total cost: **₹0 / $0** on the free tiers (see [Limits](#7-free-tier-limits-and-possible-charges)).

---

## 1. Create the cloud database (Supabase)

1. Go to <https://supabase.com> → **Start your project** → sign in with GitHub.
2. **New project**
   - Name: `campusvoice`
   - Database password: click **Generate a password** and **save it somewhere safe**. You need it in step 3.
   - Region: the one closest to you (e.g. *South Asia (Mumbai)*). Pick the **same region** for Render if possible.
   - Plan: **Free**.
3. Wait ~2 minutes for provisioning. Then click **Connect** (top bar of the project page).
4. Under **Connection string**, choose **Session pooler**. Copy the URI. It looks like:
   ```
   postgresql://postgres.abcdefghijkl:[YOUR-PASSWORD]@aws-0-ap-south-1.pooler.supabase.com:5432/postgres
   ```
   Replace `[YOUR-PASSWORD]` with your database password. If the password contains any of `@ : / ? # %`, URL-encode them (e.g. `@` → `%40`), or reset the password to one with only letters and digits.

   > **Why the Session pooler and not the "Direct connection"?** On the free plan the direct host (`db.xxxx.supabase.co`) is reachable only over **IPv6**. Render and many home networks use IPv4, so the direct URL fails with "could not translate host name" or "Network is unreachable". The pooler supports IPv4.

## 2. Create the tables

Pick **one** option.

**Option A: Supabase SQL Editor (easiest)**
Supabase dashboard → **SQL Editor** → **New query** → paste all of [`database/schema.sql`](../database/schema.sql) → **Run**. You should see "Success. No rows returned". Check **Table Editor**: `feedback`, `admins` and `students` now exist.

**Option B: from your computer**
```bash
cd backend
copy .env.example .env          # macOS/Linux: cp .env.example .env
# edit .env → paste DATABASE_URL, set SECRET_KEY
python manage.py init-db
python manage.py check-db       # prints the server version and the 3 tables
```

The schema also **enables Row Level Security** and revokes access from Supabase's public `anon` role. Supabase automatically publishes every table through a REST API that works with the public "anon key". These two settings make sure nobody can read student data through that API. Only our backend, which holds the private connection string, can access the tables.

## 3. Create the first admin account

Admins are never created from the website (that would let anyone become an admin). Run this once from your computer, with `DATABASE_URL` in `backend/.env` pointing at Supabase:

```bash
cd backend
python manage.py create-admin
# Admin username: admin
# Admin password: ********   (min 8 chars, letters + digits)
```

The same command resets the password of an existing admin.

## 4. Test locally against Supabase (optional but recommended)

```bash
cd backend
python app.py
```
Open <http://localhost:5000>, submit feedback, then log in at <http://localhost:5000/login.html>. In Supabase → **Table Editor → feedback**, you can see the row appear. This proves your laptop talks to the cloud database.

## 5. Push the code to GitHub

```bash
cd Cloud_Feedback_System
git init
git add .
git status            # make sure backend/.env is NOT listed (it is in .gitignore)
git commit -m "Cloud feedback system"
git branch -M main
git remote add origin https://github.com/<your-username>/cloud-feedback-system.git
git push -u origin main
```
Create the empty repository on GitHub first (**New repository**, no README).

## 6. Deploy the web service (Render)

1. Go to <https://render.com> → sign in with GitHub.
2. **New + → Blueprint** → select your repository. Render finds [`render.yaml`](../render.yaml) and shows one service, `campusvoice`.
3. It asks for the values marked `sync: false`:
   - `DATABASE_URL` = the Supabase Session pooler URI from step 1 (with your password).
4. Click **Apply**. Render installs `backend/requirements.txt` and starts `gunicorn`. The first build takes 2–4 minutes.
5. When the status turns **Live**, open the URL shown, e.g. `https://campusvoice.onrender.com`.
   - `https://campusvoice.onrender.com/api/health` should show `"database": "connected"`.

`SECRET_KEY` is generated by Render automatically (`generateValue: true`). `FLASK_ENV=production` turns on `Secure` cookies and HSTS.

**Without a Blueprint (manual alternative):** New + → **Web Service** → pick the repo →
Runtime *Python 3* · Build command `pip install -r backend/requirements.txt` ·
Start command `cd backend && gunicorn app:app --workers 1 --threads 4 --timeout 60 --bind 0.0.0.0:$PORT` ·
Instance type *Free* · Environment variables: `FLASK_ENV=production`, `SECRET_KEY=<64 random hex chars>`, `DATABASE_URL=<pooler URI>`, `PYTHON_VERSION=3.12.7`.

### Verify the deployment

From your computer:
```bash
cd backend
python verify_deployment.py https://campusvoice.onrender.com
```
The script checks that the site is reachable over the internet and that the backend reports a live database connection. It then submits one feedback (student ID `VERIFY-…`), logs in as admin and reads that row back from Supabase. It finishes by confirming that anonymous users get `401`. Then open the URL on your **phone using mobile data** (not Wi-Fi) to demonstrate remote access from a different network.

## 7. Free-tier limits and possible charges

| Service | Free tier | What to watch |
|---|---|---|
| **Render web service** | 750 instance-hours/month (enough for one always-on service), 512 MB RAM | Sleeps after **15 min without traffic**; the next visit takes **~30–60 s** to wake up. Open the site a minute before a demo. No charges unless you change the instance type to a paid plan. |
| **Supabase** | 500 MB database, 5 GB egress, 2 free projects | Free projects are **paused after 7 days of inactivity**. Restore them from the dashboard (data is kept). No charges on the Free plan. Spend caps are on by default for paid plans. |
| **GitHub** | Free public/private repos | — |

Neither service needs a credit card for the free tier as of writing. Check their pricing pages before upgrading anything.

## 8. Alternative: frontend on a separate Render Static Site

The recommended setup serves the frontend from Flask (one origin). If your evaluator specifically wants a **separate static host**:

1. Render → **New + → Static Site** → same repo → *Publish directory*: `frontend` → *Build command*: leave empty.
2. In `frontend/js/config.js` set `API_BASE_URL: "https://campusvoice.onrender.com"` and push.
3. On the **web service**, add environment variables:
   ```
   CORS_ORIGINS=https://campusvoice-frontend.onrender.com
   SESSION_COOKIE_SAMESITE=None
   ```
4. **Caveat:** `onrender.com` is a "public suffix", so the two sub-domains count as **different sites**. The admin session cookie then becomes a *third-party cookie*. Safari blocks these by default, and so do Chrome/Edge in some privacy modes, so admin login may fail in those browsers. The single-service setup has no such problem. Use a custom domain for both (`app.example.com` + `api.example.com`) if you need two services in production.

## 9. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `/api/health` → `503 "database": "unreachable"` | Wrong `DATABASE_URL`, wrong password, or the Supabase project is paused. Use the **Session pooler** URI. Check the Render logs for the exact psycopg2 error. |
| Deploy fails on the health check | Same as above: Render keeps the old version live until `/api/health` returns 200. |
| `password authentication failed` | The password in the URI is wrong or contains un-encoded special characters. |
| Admin login works locally but not on Render | You created the admin in a different database. Run `create-admin` with the **Supabase** `DATABASE_URL`. |
| `429 Too many requests` | Rate limit hit (5 submissions or 5 admin logins per minute per IP). Wait one minute. |
| First page load takes ~50 s | The free Render instance was asleep. This is expected. |
